# Fake data seeder

The seeder inserts demo rows directly into the Oracle tables. Liquibase remains
responsible for creating and updating the schema; it does not load the fake data.

## Docker Compose

Set `ORACLE_PASSWORD` in the repository `.env` file. Start the regular stack
without fake data:

```powershell
docker compose up --build
```

To include the seeder in the development stack:

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

This applies schema migrations, runs the seeder, then starts the API. To run
just the development seeder:

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm seeder
```

## Run locally

For an Oracle database whose schema is already up to date:

```powershell
Set-Location faker
npm install
$env:ORACLE_USER = "SYSTEM"
$env:ORACLE_PASSWORD = "your-oracle-password"
$env:ORACLE_CONNECT_STRING = "localhost:1521/FREEPDB1"
npm start
```

## What gets seeded

All data is generated by `fake-data.js` from a fixed Faker seed (`defaultSeed`, override with `FAKER_SEED`)
and the current date, so a run is reproducible for a given day and database state. Names, addresses, phone
numbers and fees (LKR) follow the app's Sri Lankan context; emails use the reserved `example.*` domains.

| Table | Rows (empty database) | Notes |
| --- | --- | --- |
| Clinics | 8 | Uneven sizes (2 to 12 providers); one has no phone number. The first is the marker clinic. |
| Providers | 58 | 46 verified providers in clinics, specialties weighted per clinic; 6 verified providers without a clinic, 4 pending and 2 rejected self-registrations. Gender and fee are filled for most. |
| ClinicJoinRequests | ~20 | Approved requests for providers who joined by self-registration, earlier rejected or cancelled requests, and pending requests (at most one per provider) spread over several clinics. Only verified providers have requests. |
| AllergyTypes | 22 | Common drug, food, contact, environmental and insect allergies. Existing types with the same name (case-insensitive) are reused. |
| Patients | top-up to 600 | Ages from infants to 90s (about 20% children); 10% registered in the last two months. |
| PatientAllergies | ~320 | About 38% of patients have one or more; severity and notes depend on the allergen. |
| Appointments | ~5,000 | From 10 weeks ago to 5 weeks ahead, Monday to Saturday, on the 20-minute slot grid between 08:00 and 16:00 UTC (the API's `ClinicManagementSettings`). |

Appointment rules:

- A provider never has two requested/confirmed/completed appointments in the same slot. A cancelled or
  declined slot is sometimes rebooked by another patient.
- A patient has at most one appointment per day, and only with specialties that fit their age (pediatrics
  for children, obstetrics and gynecology for women, and so on). Patients mostly see their own primary-care
  provider and the specialists they were referred to.
- Statuses follow the domain transitions. Past appointments are mostly `COMPLETED`, with some `CANCELLED`
  and `DECLINED` and a few recent ones not yet closed out. Future ones are mostly `CONFIRMED` or `REQUESTED`.
  `CreatedAtUtc`, `StatusChangedAtUtc` and `UpdatedAtUtc` are consistent with that history.
- Appointments are only booked with verified providers who belong to a clinic, after the patient registered
  and the provider joined.

`Users` and `ClinicAdmins` are not seeded. A user row needs a real Keycloak subject to be any use, and
`ClinicAdmins.UserId` is required. Patients and providers are left without a `UserId`, as they are for
profiles created by an administrator. To manage a seeded clinic, sign in and grant your own user clinic-admin
or platform-admin rights.

## Re-running

The seeder inserts everything in a single transaction. That includes a marker clinic,
`Training Clinic (clinic-management-demo-v2)`, which has a fixed Id. If a clinic with that name or Id already
exists, the seeder does nothing. A failed run rolls back completely, so it can be retried.

Otherwise it tops the Patients table up to 600 and books appointments for both new and existing patients.
It avoids existing patient emails and allergy type names. A database seeded by the earlier v1 seeder gets the
v2 data added once. Remove the `oracle-data` volume (`docker compose down -v`) for a clean data set.

## Tests

```powershell
npm test
```

The tests check the generated rows against the schema (column lengths, required columns, unique keys,
foreign keys and check constraints) and the domain rules (status transitions, clinic hours, no
double-booking). They also check that generation is deterministic. Set `SEED_TEST_NOW` and/or
`SEED_TEST_SEED` to run the same checks for another reference time or seed.
